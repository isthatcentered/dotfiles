The editorial read

Consensus before detail
01 / clear favorite

Own the runtime

Both reports choose a self-contained Node CLI with pinned ESLint dependencies and an adapter boundary. It works even when the target has no ESLint install.

02 / main fork

Central policy or local context?

The hard product choice is config authority. A central config is predictable; a target-local overlay respects framework and monorepo settings.

03 / later

Keep expansion cheap

Containers and a Go orchestrator make more sense once the suite spans runtimes. For ESLint alone, both add machinery without improving the first release.
