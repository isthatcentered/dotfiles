Real Neovim behavior vs. design choices
  
Native: v selects characters inclusively; V selects whole lines. Esc cancels, o swaps selection ends. Extmarks can highlight ranges, display signs and follow edits without dirtying the buffer. The prompt models default vim.ui.input; its appearance can change with your UI plugins.

  
Proposed mappings: Space R adds feedback (Normal mode uses the current line); Space rr opens a quickfix-style list; Space rc collects and clears. Those mappings are custom behavior, not built into Neovim. Overlapping comments stay separate; no tags. Comment input is single-line for this first pass.

  
JSON contract: paths relative to the project root; lines and UTF-8 byte columns start at 1; the end position is exclusive. A whole-line selection ends at column 1 of the following line, including an EOF boundary. Coordinates are read at collection time, so they reflect edits. Copy failure keeps feedback intact. Reloading this mock, like closing Neovim under this proposal, loses pending feedback.

  
Scope of this simulator: h j k l, arrows, 0, $, gg, G, v, V, o, Esc and the proposed leader keys. No counts, block selection, arbitrary editing, undo, drag selection or full Vim engine. File tabs stand in for buffer switching; they exit Visual mode. Deleting an annotated range, wiping a buffer and undo policy still need a real-Neovim implementation decision.

  
Grounded in Neovim v0.12.6: Visual mode, extmarks and signs, input prompt implementation.
